# 双路径个人作品集设计

## 目标

建立一个可部署到 GitHub Pages 的中文优先静态个人网站。它不把同一份简历压缩给所有人看，而是让访问者从首页进入适合自己的叙事：AI 应用工程招聘者看到可靠的交付能力；博士导师看到可追溯的研究问题、论文与实验习惯。

## 信息架构

- `/`：入口页。两张不对称的入口海报分别通向工程与研究路径；同时保留 GitHub、博客、B 站和公众号的统一出口。
- `/engineering/`：面向招聘者。按“现在能交付什么 → 做过什么 → 如何验证 → 持续输出”组织：企业级 AI 应用能力、开源项目、精选博客与教育经历。
- `/research/`：面向导师。按“研究问题 → 论文 → 方法与实验 → 研究型工程能力”组织：多语种模型、跨语言检索、开放域问答与多模态空间理解。

主页不重复两页内容。两个详情页共享个人身份、外部链接和页脚，但使用不同的内容顺序与文案，不做简单换肤。

## 内容取舍与公开边界

只使用用户提供或公开可核验的材料。企业经历将描述为能力与职责，例如权限隔离、工具接入、评测和交付；不出现内部代码、客户数据、业务库结构、未公开指标或内部项目链接。论文保留题目、作者位次、会议/期刊和公开链接。项目优先链接到公开 GitHub 仓库。

联系方式默认仅保留邮箱入口，不展示电话、生日、住址或证件信息。B 站使用用户提供的主页链接；微信公众号以“程艺的编程之路”作为可识别的文字入口，不虚构可点击主页或运营数据。

## 内容模型

内容集中写在 `assets/site-data.js`，由三个页面读取。每一项作品至少包含标题、角色、短描述、可选技术标签和外链。这样后续更新论文、博客或项目时不必同时修改三份 HTML。

初版的代表内容：

- 工程：企业 AI 应用交付（脱敏）、RagFlow 实习、Orchestra、AIGC Hidden Metadata、音乐的奉献导赏视频生成器。
- 研究：2025《计算机科学》一作、2024《计算机研究与发展》二作、ACL 2025 三作、SIGIR 2023 数据标注贡献，以及对应研究问题脉络。
- 输出：GitHub `aopstudio`、博客 `neusoftware.top`、B 站 `space.bilibili.com/14938115`、公众号“程艺的编程之路”。

## 视觉与交互

整体是“实验档案 / 编辑部样张”而非 SaaS 卡片模板。主色为暖纸白、深墨绿黑与朱红；标题采用中文宋体系统回退与 serif 组合，正文采用人文无衬线回退。页面使用细网格、编号、页边注和叠加的索引文字建立档案感。

工程页更偏深色工作台：高密度、轻微网格和结果索引；研究页更像印刷论文集：大留白、红色章节号和纵向研究线。首屏加载采用一次性的错峰进入动画，滚动进入使用低干扰 reveal；`prefers-reduced-motion` 会关闭动画。小屏变为单列，所有外链与文字保持可触达和高对比度。

## 技术与部署

采用零构建依赖的 HTML/CSS/JavaScript：根目录 `index.html` 和两个目录式路由。GitHub Pages 只需从仓库默认分支部署根目录，不依赖服务端或环境变量。站点会包含 `404.html`、`README.md` 部署说明、`robots.txt` 和基本元信息。

## 验收标准

1. 三个 URL 在静态服务器和 GitHub Pages 子路径下都能正常加载。
2. 首页 10 秒内可辨别两个受众路径；每个详情页在首屏即可知道此页为谁而写。
3. 外链均为用户提供或公开仓库/文章地址；没有内部信息和无证据的数据指标。
4. 375px 宽和桌面宽度下没有水平滚动，键盘可访问链接，减少动态偏好有效。
5. README 写清创建 GitHub 仓库、推送、开启 Pages 与自定义域名（可选）的步骤，但不替用户发布。
